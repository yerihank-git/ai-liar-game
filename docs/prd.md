# LiarGame AI MVP PRD

## 핵심 정보

**목적**: 친구들과 링크 하나로 즉시 라이어게임을 시작할 수 있으며, AI가 플레이어로 참여하고 게임을 분석해주는 실시간 멀티플레이어 웹앱.

**사용자**: 온라인으로 파티게임을 즐기려는 친구 그룹, 소규모 인원(2~3명)으로 게임하고 싶은 사람들, AI와 심리전을 즐기고 싶은 게이머.

---

## 문제 정의

### 시장 배경

소셜 디덕션 게임(Social Deduction Game) 장르는 글로벌 파티게임 시장에서 가장 빠르게 성장하는 카테고리 중 하나다. Among Us는 출시 이후 5억 회 이상 다운로드되며 비대면 친목 게임의 수요를 입증했고, 국내에서도 마피아42, 게리의 모드 등 소셜 디덕션 게임 플레이어 저변이 형성되어 있다.

국내 모바일 게임 이용자는 약 3,200만 명(2023년 기준)으로 추정되며, 그 중 캐주얼·파티게임 장르 이용자는 약 30~40%를 차지한다. 10~30대 친구 그룹 단위로 즐기는 파티게임 문화는 카카오톡·디스코드 기반 온라인 모임에서 빠르게 확산되고 있다.

### 핵심 페인포인트

| # | 페인포인트 | 규모 및 근거 |
|---|-----------|-------------|
| P1 | **인원 부족 문제** — 라이어게임은 최소 4~5명이 필요해 3명 이하 그룹은 플레이 불가 | 소규모 친구 그룹(2~4명)은 파티게임의 핵심 타겟이나 진입 장벽 존재 |
| P2 | **기존 앱의 AI 부재** — 현존 온라인 라이어게임 앱은 단순 키워드 배정 수준, AI 플레이어 기능 없음 | 경쟁 앱 검토 결과 AI 플레이어 통합 서비스 전무 |
| P3 | **온라인 전환 시 몰입 저하** — 오프라인 라이어게임을 카톡/음성채팅으로 진행하면 진행 정리가 산만하고 승패 판정 혼선 발생 | 별도 진행 도구 없이 메신저만 쓸 때 게임 흐름 유지 어려움 |

## 게임 규칙

### 기본 라이어 모드

- 참가자 중 **1명**이 **라이어**로 배정됨
- 나머지 플레이어는 **시민**으로 동일한 제시어를 받음
- **라이어**는 제시어를 알 수 없음
- 각 플레이어가 순서대로 제시어를 설명함
- 라이어는 다른 사람의 설명을 참고하여 들키지 않게 설명함
- 토론 후 전원 투표로 라이어를 지목함

**승패 판정:**

- 라이어가 지목됨 + 정답 키워드를 못 맞힘 → **시민 승리**
- 라이어가 지목됨 + 정답 키워드를 맞힘 → **라이어 승리** (역전)
- 라이어가 지목되지 않음 → **라이어 승리**

### 바보 모드

- 대부분의 플레이어는 **같은 제시어**를 받음 (시민)
- **바보 1명**만 **다른 제시어**를 받음 (같은 카테고리 내 유사하지만 다른 단어)
- 바보는 자기 단어가 다르다는 사실을 모르고, 자기 단어 기준으로 설명함
- 시민들은 미묘하게 다른 느낌을 캐치하여 바보를 찾아냄

**승패 판정:**

- 바보가 지목됨 → **시민 승리** (바보 발각)
- 바보가 지목되지 않음 → **바보 승리** (바보 생존)

## 사용자 여정

```
1. [홈 페이지]
   ↓ "방 만들기" 버튼 클릭 → 닉네임 입력

2. [대기실 페이지] (방장)
   ↓ 게임 설정 (모드 선택, AI 플레이어 추가, 카테고리 선택)
   ↓ 초대 링크 복사 → 친구에게 공유
   ↓ 다른 플레이어들 입장 대기
   ↓ 최소 인원(3명) 충족 시 "게임 시작" 버튼 활성화
   ↓ "게임 시작" 클릭

   [대기실 페이지] (참가자)
   ↓ 초대 링크 접속 → 닉네임 입력 → 대기실 입장
   ↓ 방장의 게임 시작 대기

3. [게임 진행 페이지 - 역할 확인 단계]
   ↓ 자신의 역할(시민/라이어/바보) 및 키워드 확인
   ↓ 확인 완료 버튼 클릭 (전원 확인 대기)

4. [게임 진행 페이지 - 설명 단계]
   ↓ 턴 순서에 따라 각 플레이어가 키워드 설명 입력
   ↓ AI 플레이어는 자동으로 설명 생성
   ↓ 전원 설명 완료

5. [게임 진행 페이지 - 토론 단계]
   ↓ 자유 채팅으로 토론 (제한 시간)
   ↓ AI 플레이어도 토론에 참여

6. [게임 진행 페이지 - 투표 단계]
   ↓ 각 플레이어가 라이어(또는 바보)로 의심되는 사람에게 투표
   ↓ AI 플레이어도 투표 참여
   ↓ 전원 투표 완료

7. [게임 진행 페이지 - 최후의 변론 단계] (기본 모드에서 라이어가 지목당한 경우만)
   ↓ 라이어가 정답 키워드 맞히기 시도

8. [결과 페이지]
   ↓ 승패 결과 표시
   ↓ 역할 공개 (누가 라이어/바보였는지)
   ↓ AI 사후 분석 표시 (각 설명 분석, 핵심 단서, 의심 포인트)

   [다시하기] → 대기실로 이동 (같은 멤버 유지)
   [나가기] → 홈 페이지로 이동
```

### 게임 진행 페이지 (`/room/[roomId]` — 게임 중 각 phase)

> **구현 기능:** `F006`~`F010`, `F012`~`F014`, `F017` | **인증:** 불필요

| 항목 | 내용 |
|------|------|
| **역할** | 게임의 모든 플레이 단계를 하나의 페이지에서 phase 전환으로 처리 |
| **진입 경로** | 대기실에서 게임 시작 |

#### Phase: role_reveal (역할 확인)

- 자신의 역할 카드 표시 (시민: 키워드 표시 / 라이어: "당신은 라이어입니다" / 바보: 다른 키워드 표시)
- 카드를 탭하면 뒤집어서 역할 확인
- **"확인 완료"** 버튼 클릭
- 전원 확인 시 다음 단계로 자동 전환

#### Phase: description (설명 단계)

- 상단에 현재 턴 플레이어와 타이머 표시
- 이전 플레이어들의 설명 목록 표시
- 자신의 턴: 텍스트 입력 필드 + **"제출"** 버튼
- AI 턴: 2~4초 딜레이 후 AI 설명 자동 표시 (F008)
- 타이머 초과 시 자동 빈 제출 처리
- 전원 완료 시 토론 단계로 전환

#### Phase: discussion (토론 단계)

- 모든 설명 요약 패널 (상단)
- 실시간 채팅 UI (F013)
- AI 플레이어의 자동 채팅 참여 (2~3회)
- 토론 타이머
- 타이머 종료 시 투표 단계로 자동 전환

#### Phase: vote (투표 단계)

- 플레이어 목록에서 투표 대상 선택
- 자기 자신 투표 불가
- AI 플레이어 자동 투표 (F009)
- 투표 현황 (투표 완료 인원 표시, 내용은 비공개)
- 전원 투표 완료 또는 타이머 종료 시 결과 처리

#### Phase: final_defense (최후의 변론 — 기본 모드 한정, 조건부)

- 최다 득표자가 라이어인 경우에만 활성화
- 라이어에게 정답 키워드 입력 필드 제공 (F010)
- 다른 플레이어는 대기 화면
- 제한 시간 내 입력 또는 타이머 종료

| **다음 이동** | 게임 종료 → 결과 페이지 |

## AI 연동 (Claude API)

모든 AI 호출은 **Next.js API Routes (Route Handlers)** 를 통해 서버사이드에서 실행. API 키는 서버 환경변수에만 존재.

### AI-1: 키워드 쌍 생성 (`POST /api/ai/keywords`)

- **호출 시점**: 게임 시작 시 (바보 모드일 때)
- **입력**: 카테고리명
- **프롬프트 전략**: "해당 카테고리에서 연관되지만 미묘하게 다른 단어 쌍을 생성. 시민 키워드와 바보 키워드는 같은 범주에 속하지만 구체적으로 다른 것이어야 함."
- **출력**: `{ keyword: string, foolKeyword: string }`
- **예시**: 카테고리 "음식" → `{ keyword: "떡볶이", foolKeyword: "라볶이" }`

### AI-2: AI 플레이어 설명 생성 (`POST /api/ai/describe`)

- **호출 시점**: 설명 단계에서 AI 플레이어의 턴
- **입력**: AI의 역할(시민/라이어/바보), 키워드(시민/바보일 때), 이전 플레이어들의 설명 목록, 카테고리
- **역할별 프롬프트 전략**:

  | 역할 | 핵심 지시 | 전략적 의도 |
  |------|---------|-----------|
  | **시민** | 키워드를 직접 언급하지 않고 연상되는 특징·경험·감각을 1~2문장으로 설명. 앞 플레이어와 겹치지 않는 새로운 관점 채택 | 자신이 키워드를 알고 있다는 사실을 자연스럽게 드러내되 키워드 직접 노출 금지 |
  | **라이어** | 이전 설명들에서 공통 패턴을 추론하여 키워드를 유추. 구체적 묘사 없이 모호한 상위 개념으로만 설명. 과도하게 동조하거나 반박하지 않음 | 키워드를 모른다는 사실을 숨기며 생존. 너무 자세하면 틀릴 위험, 너무 모호하면 의심받는 균형 유지 |
  | **바보** | 자신이 받은 키워드(바보 키워드)를 기준으로 자연스럽고 자신있게 설명. 다른 사람의 설명과 미묘하게 다르더라도 당당하게 진술 | 자신의 키워드가 다르다는 사실을 모르는 상태 연출. 지나치게 어색한 설명은 금지 |

- **출력**: `{ description: string }`
- **의도적 딜레이**: 2~4초 랜덤 딜레이로 사람처럼 연출

### AI-3: AI 플레이어 토론 참여 (`POST /api/ai/discuss`)

- **호출 시점**: 토론 단계에서 일정 간격 (30초마다 또는 메시지 5개마다)
- **입력**: AI의 역할, 모든 설명, 지금까지의 채팅 내역
- **역할별 프롬프트 전략**:

  | 역할 | 토론 행동 패턴 |
  |------|-------------|
  | **시민** | 설명 간 불일치를 지적하며 의심 후보를 좁혀감. 논리적 근거 제시. 다른 시민의 의심에 동조하거나 반박하며 토론 주도 |
  | **라이어** | 다른 플레이어에게 의심을 분산시키는 발언 우선. 자신에 대한 의심은 감정적으로 부정하거나 화제 전환. 필요 시 무고한 시민을 타겟으로 지목 |
  | **바보** | 자신의 설명이 다른 사람과 다르다는 지적에 방어적 반응. 자신의 키워드가 맞다는 확신으로 의아한 반응 연출. 의도치 않게 혼란을 가중시키는 발언 가능 |

- **출력**: `{ message: string }`

### AI-4: AI 플레이어 투표 (`POST /api/ai/vote`)

- **호출 시점**: 투표 단계 시작 시
- **입력**: AI의 역할, 모든 설명, 토론 내역, 플레이어 목록
- **역할별 프롬프트 전략**:

  | 역할 | 투표 전략 |
  |------|---------|
  | **시민** | 설명의 모호함·비일관성·이전 설명과의 편차를 종합 점수화하여 가장 의심스러운 플레이어 선택. 토론에서 방어적 발언이 많은 플레이어 가중치 |
  | **라이어** | 자신을 제외하고 가장 설명이 독특하거나 소수 의견인 플레이어를 지목하여 의혹 분산. 시민들 사이 이미 의심받는 플레이어 편승 투표로 자연스러운 연기 |
  | **바보** | 자신의 설명과 가장 다른 설명을 한 플레이어를 지목. 자신이 바보임을 모르므로 가장 "이상한" 설명을 한 사람(실제로는 라이어일 수 있음)에게 투표 |

- **출력**: `{ targetPlayerId: string, reasoning: string }`

### AI-5: 사후 분석 생성 (`POST /api/ai/analyze`)

- **호출 시점**: 게임 종료 시 (결과 단계 진입)
- **입력**: 게임 모드, 모든 플레이어 역할, 키워드, 모든 설명, 투표 결과, 최종 결과
- **프롬프트 전략**: "게임 해설자로서 각 설명을 분석하고, 핵심 단서와 전환점을 짚어줘."
- **출력**: `{ descriptionAnalyses: [{playerId, suspicionLevel, analysis}], keyMoments: string[], liarStrategy: string, tips: string[] }`
