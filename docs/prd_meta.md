# 역할 및 컨텍스트

너는 실시간 멀티플레이어 웹 게임과 AI 에이전트 통합에 깊은 경험을 가진 시니어 프로덕트 매니저야.
파티게임 UX 설계, WebSocket 기반 실시간 동기화, LLM을 활용한 게임 AI 구현에 정통하고 있어.

# 프로젝트 개요

"LiarGame AI" — AI가 플레이어로 참여하는 실시간 멀티플레이어 라이어게임 웹앱

## 핵심 가치 제안
친구들과 링크 하나로 즉시 라이어게임을 시작할 수 있으며,
AI가 플레이어로 참여하여 인원이 부족해도 게임을 즐길 수 있고,
AI의 실시간 분석으로 게임의 재미와 전략적 깊이를 더한다.

# 린캔버스 정의 (이 제품 자체)

| 항목 | 내용 |
|---|---|
| **문제** | ① 라이어게임은 최소 4~5명이 필요해 인원 모으기 어려움 ② 기존 온라인 라이어게임 앱은 단순 키워드 배정 수준으로 AI 플레이어가 없음 ③ 오프라인 라이어게임을 온라인으로 전환하면 진행이 산만해지고 몰입감이 떨어짐 |
| **고객 세그먼트** | 친구들과 온라인으로 파티게임을 즐기려는 10~30대, 인원이 부족한 소규모 그룹(2~3명), AI와의 심리 대결을 즐기려는 게이머 |
| **고유 가치 제안** | "링크 하나로 시작하고, AI가 빈자리를 채우고, AI가 게임을 분석해준다" |
| **솔루션** | ① 회원가입 없이 링크로 즉시 입장하는 실시간 게임룸 ② Claude AI가 시민/라이어/바보 역할로 플레이에 참여 ③ AI 사후 분석으로 각 설명의 의심 포인트와 핵심 단서 제공 |
| **채널** | 카카오톡/메신저 초대 링크 공유, 소셜 미디어, 게임 커뮤니티 |
| **수익원** | 무료 (MVP 단계), 추후 커스텀 카테고리팩 / 프리미엄 기능 |
| **비용 구조** | Claude API 호출 비용, Supabase 무료 플랜, Vercel 무료 호스팅 |
| **핵심 지표** | 방 생성 수, 게임 완료율(시작 대비 결과까지 도달), 평균 게임 시간, 재게임률, AI 플레이어 사용 비율 |
| **경쟁 우위** | Claude AI의 자연스러운 한국어 설명 생성 능력, AI가 실제 플레이어로 참여하는 유일한 라이어게임, 바보 모드의 AI 키워드 쌍 자동 생성 |

# PRD 작성 요청

위 린캔버스를 기반으로 아래 구조의 PRD를 작성해줘.

## 1. 제품 개요
- 제품명, 한줄 설명, 타겟 사용자, 핵심 문제 정의

## 2. 게임 규칙
- 기본 라이어 모드 상세 규칙
- 바보 모드 상세 규칙
- 승패 판정 로직

## 3. 사용자 페르소나 (최소 2개)
- 이름, 배경, 목표, 페인포인트, 이 제품을 쓰는 시나리오

## 4. 유저 플로우 (핵심 시나리오)
- **플로우 A**: 방장 → 방 생성 → 설정 → 초대 → 게임 진행 → 결과
- **플로우 B**: 참가자 → 초대 링크 입장 → 게임 진행 → 결과
- 각 플로우를 단계별로 상세히 기술

## 5. 기능 요구사항

### 5.1 MVP (Phase 1)
- 방 생성/입장 (닉네임만, 회원가입 없음)
- 게임 모드 선택 (기본 라이어 / 바보 모드)
- AI 플레이어 추가 (최대 2명)
- 카테고리 및 키워드 시스템 (AI 생성 포함)
- 역할 배정, 턴제 설명, 토론 채팅, 투표, 라이어 정답 맞히기
- AI 플레이어 행동 (설명 생성, 토론 참여, 투표)
- 결과 발표 및 AI 사후 분석
- 실시간 동기화 (Supabase Realtime)

### 5.2 Phase 2
- AI 의심도 힌트 (각 설명에 실시간 의심도 점수)
- 커스텀 키워드 팩 생성
- 게임 히스토리 / 통계
- 관전 모드

### 5.3 Phase 3
- 음성 채팅 연동
- 소셜 로그인 및 프로필
- 랭킹 시스템
- 3라운드 이상 연속 게임 모드

## 6. 비기능 요구사항
- 성능: 실시간 메시지 지연 500ms 이내, AI 응답 3초 이내
- 반응형 디자인 (모바일 우선 — 파티게임 특성상 모바일 사용 비율 높음)
- 동시 접속: 방당 최대 8명
- 데이터 보존: 게임 완료 후 24시간 뒤 자동 삭제

## 7. 기술 스택 제안
- Frontend: Next.js (App Router), TypeScript, React 19, TailwindCSS v4, shadcn/ui
- 상태관리: Zustand
- 실시간: Supabase Realtime (Postgres Changes + Broadcast + Presence)
- DB: Supabase PostgreSQL
- AI: Claude API (Anthropic SDK)
- 배포: Vercel

## 8. AI 연동 설계
- 키워드 쌍 생성 (바보 모드)
- AI 플레이어 설명 생성 (역할별 전략)
- AI 토론 참여
- AI 투표
- 게임 사후 분석
- 각 연동 포인트의 프롬프트 전략과 호출 시점 명세

## 9. 성공 지표 (MVP)

| 지표 | 목표 |
|---|---|
| 게임 완료율 | 시작한 방의 70% 이상 게임 완료 |
| 재게임률 | 결과 후 "다시하기" 비율 50% 이상 |
| AI 플레이어 사용률 | 전체 게임의 40% 이상에서 AI 플레이어 포함 |
| 평균 게임 시간 | 10분 이내 |

## 10. 리스크 및 완화 방안
- AI 응답 지연 → 의도적 딜레이(2~4초)로 자연스러운 대기 연출 + 타임아웃 처리
- AI 부자연스러운 설명 → 역할별 세분화된 프롬프트 + 이전 설명 컨텍스트 주입
- 플레이어 이탈 → 30초 대기 후 AI로 자동 대체 또는 스킵 처리
- Supabase 무료 한도 → 24시간 후 데이터 자동 삭제로 DB 용량 관리
- Claude API 비용 → 게임당 API 호출 횟수 제한, 토큰 제한
